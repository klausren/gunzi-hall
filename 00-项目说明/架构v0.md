## 三、模块拆分与命令模式设计

### 3.1 领域模型（DDD Lite）

```
game-domain/
├── card/         # 牌（单副/三副）、花色、点数、组合
├── deck/         # 牌组、洗牌、切牌
├── player/       # 玩家抽象（含真实玩家/AI Agent）
├── room/         # 房间生命周期、状态机
├── tricks/       # 一轮出牌过程、最高出牌者判定
├── scoring/      # 抠庄、亮王、得分
├── tribute/      # 进贡/还贡/抗贡（最复杂，必须子状态机）
└── action/       # 命令模式：所有玩家动作
```

### 3.2 命令模式核心类

```java
// 每个动作都是命令，支持序列化、回放、校验
public interface GameCommand extends Serializable {
    String commandId();     // 唯一 UUID
    long    roomId();
    long    playerId();
    long    tick();         // 顺序号，用于回放
    Result  execute(GameRoom ctx);  // 执行 + 返回结果
    Result  rollback(GameRoom ctx); // 可选回滚（仅本地调试用）
}

// 例子：抠庄、出牌、亮王、进贡、还贡、抗贡、退出托管...
public class PlayCardsCommand implements GameCommand { ... }
public class DeclareBankerCommand implements GameCommand { ... }
public class PayTributeCommand implements GameCommand { ... }
```

### 3.3 AI Agent 接管架构

```
玩家断线 → 战斗服心跳超时 (3-5s) 
         → 自动生成 AgentProxyPlayer 注入房间 (0 延迟)
         → Agent 决策循环: 当前局面 → 决策树查表 → 出牌命令
         → 玩家重连 → 平滑交接 → 暴露"被托管局数"给玩家
```

**关键设计：**
- `AgentProxyPlayer` 与真实玩家实现同一接口 `Player`
- 房间状态机不区分"是不是 AI"，避免双路径
- 决策引擎先用**规则版**（基于牌力评估、剩牌概率、抠庄收益），后续再叠加 LLM 决策

## 五、商业化与合规边界

| 场景 | 广告形式 | 合规检查 |
|---|---|---|
| 建房第 2 次起 | 30 秒激励视频 | ✅ 局外功能 |
| 高级记牌器（核心转化） | 30 秒激励视频（每日 5 次） | ✅ 工具/辅助 |
| 大连话方言包/动态表情 | 30 秒激励视频 | ✅ 装饰 |
| 赛后复盘"屁股尖顶" | 30 秒激励视频 | ✅ **广告必须在看完后才能看完整复盘详情，不能影响牌局公平** |
| 匹配加速 | 30 秒激励视频 | ⚠️ 不能给付费玩家不公平优势，建议**纯随机**时长（10-30s） |
| 复活 / 换牌 | - | 🚫 严禁，审核红线 |

**重要**：必须在游戏内露出"本游戏纯属娱乐，不涉及赌博"提示，并提供"投诉/举报"入口（合规要求）。

## 六、安全与反作弊

1. **命令模式 + 服务器权威**：所有命令由服务端校验后落地，客户端只是 view
2. **帧同步改为状态同步**：客户端每 tick 拉一次"自上次以来的变化"，避免客户端伪造未来 tick
3. **关键决策动作服务端二次校验**：抠庄、亮王、还贡必须服务端重算
4. **异常行为检测**：出牌时延短于人类极限（如 < 200ms 连续多张）、分数突变，自动标记
5. **Token 防重放**：每个命令 UUID 在局内唯一，重放直接拒绝
