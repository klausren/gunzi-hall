## 三、关键经验（永久记住）

### 1. UUID 大小写铁律
**Cocos 引擎 `decodeUuid(短码)` 恒输出小写**。任何资源 meta 的 uuid 若是全大写（异常情况），构建产物会按大写生成 import 文件名，但引擎加载路径是小写 → 大小写敏感 FS 找不到 → `JSON.parse("")` 黑屏。
- 症状：模拟器黑屏，console 报 `Uncaught SyntaxError: Unexpected end of JSON input`
- 检测：检查 `import/<前两字符>/` 下文件名是否全小写
- 修复：把 meta uuid 和源文件 `_id` 改成小写 + 删 library 缓存重导入

### 2. game.json 字段规则（双向雷）
| 字段类型 | 字段名 | 处理 |
|---|---|---|
| 设备/主题 | deviceOrientation / showStatusBar / backgroundColor | 必留 |
| 网络 | networkTimeout | 必留 |
| **数组 manifest** | pages / subpackages | **必须显式 `[]`**（缺则 `Object.keys(undefined)` null deref） |
| **字符串路径** | openDataContext / workers / lazyLoading | **必须 pop**（空串则报 "不能为 ''"）|

### 3. libVersion 类型铁律
- **官方类型 String**（不是数组，不是逗号分隔）
- **可用值**：`"latest"` / `"3.7.9"`（社区公认稳定值）
- **错误用法**：`"widelyUsed"` / `"game"` / `"2.30.0, 3.8.0"`（双版本串）
- **报错措辞反话**："string, string" 实际是 "应当是 string 类型"，非常迷惑

### 4. project.private.config.json 是隐形污染源
**每次开发者工具打开项目都会重写这个文件**，把我们设的 `libVersion: "3.7.9"` 改回 `"3.17.2"`。这是项目类型识别的关键污染源。

### 5. Cocos GUI 发布是反向操作
**永远不要在 Cocos 编辑器里点"发布到小游戏"按钮**——它会绕过我们 build 脚本的所有 patch，重置 game.json / project.config.json 到默认形态（portrait + widelyUsed + openDataContext: ""）。产品改动后必须重跑 `./build-wechatgame.sh`。

## 六、新成员 Windows 环境特别提醒

- **Windows 默认 `autocrlf` 会把所有 `.sh`/`.js` 转成 CRLF**——已加 `.gitattributes` 强制 LF，clone 后还需：
  ```
  git config core.autocrlf false
  ```
- **`build-wechatgame.sh` 是 macOS 专用**——Windows 跑不了，需要改成 PowerShell 或在 WSL 里跑
- **微信开发者工具路径不同**——Windows 默认装在 `C:\Program Files (x86)\微信开发者工具\`
- **依赖 JDK 17**——Windows 不要用系统 JDK 21（架构问题），装 arm64 JDK 17（详见团队协作指南）
