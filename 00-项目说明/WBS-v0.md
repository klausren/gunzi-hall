## Sprint 1: 核心战斗服骨架 (Week 1-2)

**目标**：把"牌局房间"的后端骨架搭起来，能让 4 个 bot 在里面发牌、出牌、判定胜负（不接前端 UI）

| ID | 任务 | 验收标准 |
|---|---|---|
| T-101 | 领域模型（Card、Deck、Player、Room、Action） | 单元测试覆盖各类牌型判定 |
| T-102 | 命令模式 GameCommand 接口 + 5 个实现（PlayCards/Pass/DeclareBanker/Lead/RevealTrump） | 可序列化为 JSON、可回放 |
| T-103 | 战斗服 Netty WebSocket 长连接（含心跳） | 4 个模拟客户端能稳定连接 24h |
| T-104 | 牌局状态机（WAITING→DEALING→BIDDING→PLAYING→TRIBUTE→SETTLED） | 状态转移有单元测试 |
| T-105 | Redis 状态快照 + 重连恢复 | 强制重启战斗服后房间状态可还原 |

**Demo**：命令行启动 4 个 Java 客户端，自动开局 1 局，全程不打错。

## Sprint 2: 规则引擎 — 三副牌基本玩法 (Week 3-4)

**目标**：把大连滚子的"普通出牌/管牌/一轮最大"逻辑跑通（不含抠庄/进贡/抗贡）

| ID | 任务 | 验收标准 |
|---|---|---|
| T-201 | 三副牌洗牌/切牌/发 27 张 | 模拟 1000 局无异常 |
| T-202 | 牌型识别（单/对/三张/三带二/顺子/连对/炸弹等） | 单元测试覆盖率 ≥ 90% |
| T-203 | 牌型比较与"管牌"判定 | 单/对/三张/炸弹均通过 |
| T-204 | 一轮结束判定（最后一个出牌者胜）+ 收牌 | 单元测试 |
| T-205 | 牌局结束 + 基础计分 | 集成测试 |

**Demo**：4 个 bot 玩完一局，输出完整 action log，回放脚本可重放。

## Sprint 6: AI Agent（规则版）(Week 11-12)

**目标**：Agent 能在 3 秒内稳定接管掉线玩家，且新人开局感受不到 AI

| ID | 任务 | 验收标准 |
|---|---|---|
| T-601 | 偏好向量模型（激进/保守/控场/抠庄倾向） | 配置化加载 |
| T-602 | 决策树引擎（基于牌力 + 剩牌） | 单步决策 ≤ 50ms |
| T-603 | AgentProxyPlayer 注入房间（断线 0 秒接管） | 玩家重连能无缝接力 |
| T-604 | "人类感"：随机思考时长 0.8-2.5s + 3% 错误率 | 真人测试难分 |
| T-605 | AI 失败率/可挑战性指标埋点 | Dashboard |

**Demo**：3 真人 + 1 AI 比赛，AI 行为自然。
