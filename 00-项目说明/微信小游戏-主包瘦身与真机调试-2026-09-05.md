# 微信小游戏主包瘦身 & 真机调试指南

> 日期：2026-09-05
> 适用：大连打滚子客户端（Cocos Creator 3.8.8 → 微信小游戏）
> 结论：**主包 4.5MB → 1.73MB**，真机调试的 4MB 限制已解除

---

## 一、问题现象

模拟器里游戏已完整跑通（bot 打完 9 局、结算面板正常），但点开发者工具「真机调试」时上传失败：

```
真机调试 Error：上传失败：网络请求错误，
source size 4498KB exceed max limit 4MB
（错误码 80051）
```

**关键认知**：4MB 限制**只作用于真机调试 / 上传**（代码要传到微信服务器）。
**devtool 模拟器是本机调试，不受此限制**——所以之前 4.5MB 在模拟器里照样能玩。

---

## 二、根因

Cocos 默认**全引擎模块开启**，而打滚子是纯 2D 桌游：

| 产物 | 大小 | 项目是否用到 |
|---|---|---|
| `cocos-js/_virtual_cc-*.js` | 2.8 MB | 引擎全模块，99% 用不到 |
| `cocos-js/assets/bullet.release.wasm` | 458 KB | 3D 物理引擎 ❌ |
| `cocos-js/assets/spine-*.wasm` | 200 KB | Spine 骨骼动画 ❌ |
| `assets/internal` | 676 KB | Cocos 内置资源（多为 3D 材质/贴图） |

项目实际用到的引擎能力（全量扫描 `assets/scripts/` + `main.scene` 得出）：

```
Node / Label / Graphics / Tween / Canvas / UITransform / Widget / Camera
```

纯 2D UI，没有 3D、物理、粒子、骨骼动画、音视频、瓦片地图。

---

## 三、解法：引擎功能裁剪（不是分包）

### 配置文件

`client/settings/v2/packages/engine.json`

结构说明（**重点**）：

```jsonc
{
  "modules": {
    "configs": {
      "defaultConfig": {
        "cache": {
          // 每项 _value: true/false 表示开关
          "3d":        { "_value": false },
          "spine":     { "_value": false, "_option": "spine-3.8" },
          "gfx-webgl": { "_value": true },
          ...
        },
        // ★ 真正决定打包内容的是这段，不是 cache！
        "includeModules": [
          "base", "2d", "ui", "graphics", "affine-transform",
          "gfx-webgl", "tween", "animation", "rich-text",
          "mask", "custom-pipeline"
        ],
        "noDeprecatedFeatures": { "value": true, "version": "3.8.0" }
      }
    },
    "globalConfigKey": "defaultConfig"
  }
}
```

### 本项目的裁剪清单

**保留（11 项）**

| 模块 | 用途 |
|---|---|
| `base` | 引擎核心，必留 |
| `2d` | Sprite / Label / UITransform / Canvas |
| `ui` | Widget / Layout / Button |
| `graphics` | TableUI 画牌桌、牌面 |
| `affine-transform` | 节点变换 |
| `gfx-webgl` | 渲染后端（小游戏走 WebGL1） |
| `tween` | 出牌/发牌动画 |
| `animation` | 引擎内部动画系统 |
| `rich-text` / `mask` | Label / 遮罩（保险留着） |
| `custom-pipeline` | 渲染管线，必留 |

**关闭（约 25 项）**

```
3d              gfx-webgl2      xr              primitive
particle        particle-2d     profiler        terrain
physics         physics-ammo    physics-cannon  physics-physx
physics-builtin physics-2d      physics-2d-box2d physics-2d-builtin
spine           dragon-bones    marionette      skeletal-animation
tiled-map       video           webview         audio
websocket       websocket-server
occlusion-query geometry-renderer debug-renderer light-probe
intersection-2d
```

> **注意 `websocket` 模块可以关**：我们的联机用的是**微信小游戏原生 `wx.connectSocket`**（经 `web-adapter.js` 适配），不是 cc 的 WebSocket 封装。

## 四、效果

| 指标 | 裁剪前 | 裁剪后 | 降幅 |
|---|---|---|---|
| **总大小** | **4.50 MB** ❌ | **1.73 MB** ✅ | **-62%** |
| cocos-js | 3.6 MB | 1.4 MB | -61% |
| assets | 720 KB | 212 KB | -71% |
| wasm 文件 | 658 KB | **0** | -100% |

## 六、真机调试操作指南

### 前置条件

1. **手机与电脑连同一 WiFi**
2. 电脑局域网 IP：`192.168.50.151`（`ipconfig getifaddr en0` 可查，换 WiFi 会变）
3. 战斗服已启动（8080 端口监听）

### serverUrl 三处必须同步改

手机上的 `localhost` 是手机自己，连不到电脑。**项目里有三处硬编码**：

| # | 文件 | 说明 |
|---|---|---|
| 1 | `assets/scenes/main.scene` → `"serverUrl"` | **运行时以这个为准**（场景序列化值覆盖类默认值） |
| 2 | `assets/scripts/ui/TableUI.ts` → `@property serverUrl` | 兜底默认值 |
| 3 | `assets/scripts/NetTest.ts` → `@property serverUrl` | **这个才是真正建连的组件**（Console 的 `[NetTest] 已连接服务器` 就是它） |

改完必须重跑 `./build-wechatgame.sh <appid>`。

> **排查技巧**：改完 main.scene 后，在产物 `assets/main/index.js` 里仍会 grep 到 `ws://localhost` —— 不要以为没生效。真正生效的场景值在 `assets/main/import/86/8657e25c-*.json`。`index.js` 里的只是 TS 类字段默认值。但为了不埋坑，三处仍应统一。

### 操作步骤

```
1. 启动战斗服
   pkill -f "com.gunzihall.room.ServerMain"
   python3 /tmp/start_server.py        # 确认 8080 监听

2. 重新构建
   cd client && ./build-wechatgame.sh wx72e9a9e9764f0ee1

3. 打开 devtool → 项目 gunzi-client → Cmd+B 编译
   确认模拟器仍出牌桌（验证裁剪没误伤）

4. 点工具栏「真机调试」→ 手机微信扫码
```

### 真机连不上的排查顺序

| 现象 | 原因 | 解法 |
|---|---|---|
| 扫码后进游戏但界面空白 | serverUrl 连不上 | 查三处 serverUrl 是否为本机 IP；手机与电脑是否同 WiFi |
| 提示"不在合法域名列表" | 域名校验未关 | `project.config.json` 的 `setting.urlCheck` 须为 `false`（脚本已设） |
| 提示 `ws://` 不被允许 | 生产环境限制 | 开发版/`真机调试` 模式下 `urlCheck:false` 可豁免；正式上线才需 `wss://` + 域名备案 |
| 上传报 80051 | 包 > 4MB | 跑 `./build-wechatgame.sh` 看体积守卫输出，按本文裁剪 |

## 七、后续加资源时的注意事项

剩余余量 **2.3 MB**，按优先级使用：

1. **音效**（当前 `audio` 模块已裁剪）—— 加音效前要在 `engine.json` 里把 `audio` 设回 `true` 并加进 `includeModules`，重构建。引擎模块约 +30KB，音频文件用 mp3 压缩后每条约 20-50KB。
2. **图片资源** —— 优先放 `assets/resources/` 走动态加载，或用纹理图集（TexturePacker）合并，避免散装 png 各占一块。
3. **字体** —— 中文字体动辄 3-5MB，**绝对不要整包打进去**。要么用系统字体，要么做字库裁剪（只保留用到的字）。

每次加完资源跑一次构建，看体积守卫的输出即可，不用手动算。
