## 1. 这是个什么项目

**滚子大厅**：微信小游戏形态的四人扑克游戏，实现辽宁大连地区特有的「打滚子」玩法。

- **当前形态**：微信小游戏（Cocos Creator 构建），**体验版扫码试玩**，1 名真人 + 3 名电脑对手
- **发布路线**：**体验版自娱**。不上架、不接广告、不做内购（个人主体 + 棋牌类目在政策上走不通正式上线，别被README 或新闻误导）
- **技术栈**：客户端 Cocos Creator 3.8.8 + TypeScript；服务端 Netty + Java 17 + Maven
- **代码规模**：主程序约 1.1 万行（Java 约 6700 + TypeScript 约 4500）

**规则是本项目最容易踩坑的地方**，上手第一件事是读规则手册：
`01-规则手册/打滚子规则手册-v1.1-定稿.md`

三条必须记住的规则（细节看手册）：
1. 三副牌共 **162 张**，四人两两配对成两方
2. 出牌方向是**逆时针**（`Seat.next() = (index+3)%4`，不是 index+1）
3. 真人座位是 **SOUTH**（不是 NORTH，见 6.3）

## 3. 跑起来

### 3.1 起服务端（战斗服）

```bash
cd server
mvn clean install -d skipTests   # Windows: mvn clean install -DskipTests
mvn exec:java -Dexec.mainClass=com.gunzihall.room.ServerMain
```

启动参数（**位置无关**，纯数字按`端口→房间号→托管毫秒` 认领，座位名单独识别）：

```bash
mvn exec:java -Dexec.mainClass=com.gunzihall.room.ServerMain -Dexec.args="8080 1001 1500 SOUTH"
#                          ↑端口 ↑房间号 ↑托管毫秒 ↑真人座位
```

启动成功会打印：
```
ws://<本机局域网IP>:8080/ws
```

**记下这个 IP**，手机真机调试要用。

### 3.2 跑测试

```bash
cd server && mvn test        # 应全部通过（50 个测试，10 个测试类）
```

### 3.3 起客户端

用 Cocos Creator 打开 `client/` 目录。

### 3.4 构建微信小游戏

**macOS**：
```bash
cd client
./build-wechatgame.sh              # 自动注入本机IP + 输出到 build/wechatgame/
```

**Windows**：
```powershell
cd client
powershell -ExecutionPolicy Bypass -File .\build-wechatgame.ps1
```

⚠️ **不要用 Cocos GUI 的「发布到小游戏」**，它会绕过我们的构建补丁，导致黑屏或包体超限。

### 3.5 真机调试

1. 微信开发者工具导入 `client/build/wechatgame`
2. 点「**真机调试**」（**不是「预览」，预览没有日志**）
3. 手机扫码

⚠️ **必须用「真机调试」，不能只跑模拟器**——模拟器测不出触摸交互问题。

## 5. 开发流程

### 分支与提交

**禁止直接推 main。** 走分支 + PR：

```bash
git checkout -b feat/你的功能名
# ...改代码...
git add -A && git commit -m "feat(client): 简要说明"
git push origin feat/你的功能名
```

去 GitHub 网页点 **Compare & pull request**。

提交信息用 Conventional Commits：

```
feat(client): 选中牌放大
fix(room): 修复出牌方向反了
docs(readme): 更新构建步骤
refactor(ui): 拆分 TableUI
test(domain): 补牌力比较用例
chore: 更新依赖
```

**改客户端 TypeScript 之后，提交前务必跑：**

```bash
cd client && npx tsc --noEmit -p tsconfig.json
```

Cocos 项目没有测试框架，但**至少要过类型检查**。

### 什么时候必须 `mvn install`

> ⚠️ **改了 `game-domain` 模块的代码后，必须 `mvn install -DskipTests`**，不能只跑 `mvn exec:java`。

原因：`exec:java` 的 `-pl` 参数会限定在 reactor 内，domain 模块从 `~/.m2` 解析旧 jar，你改了也不生效 → 运行时抛 `NoSuchMethodError`，而**这个异常会被线程池静默吞掉**，没有任何报错和日志。

**识别方法**：如果发一个非法 op 能正常回 `UNKNOWN_OP`（说明连接是通的），但新加的命令完全无响应 → 基本就是这个坑。

## 6. 避坑手册（全是踩过的坑，务必读）

### 6.1 🔴 `game.json` 只能有 6 个字段

多一个字段微信端就可能黑屏或报错：

```json
{
  "deviceOrientation": "landscape",
  "showStatusBar": false,
  "backgroundColor": "#000000",
  "pages": [],
  "subpackages": [],
  "networkTimeout": { "request": 5000, "connectSocket": 5000, "uploadFile": 5000, "downloadFile": 500000 }
}
```

- 必须**去掉** `openDataContext` / `workers` / `lazyLoading`
- `pages` 和 `subpackages` 必须是**显式空数组**，不能省略

### 6.2 🔴 uuid 必须全小写

Cocos 资源用 uuid 索引。如果构建产物里 uuid 带大写字母，**微信端读不到 → 黑屏**（而桌面模拟器完全正常，极难发现）。

自查：

```bash
cd client/build/wechatgame && find . -name "*.meta" | grep -E "[A-Z]"
# 输出为空 = 正常
```

### 6.3 🔴 真人座位是 SOUTH，不是 NORTH

客户端把"我"画在**屏幕最下方**，而座位名是罗盘的绝对方位（上北下南）→ **我在下 = 我在南**。

**两端必须一致**：`ServerMain.DEFAULT_HUMAN_SEAT` 与 `TableUI.mySeat`。

不一致的典型症状：启动时卡「座位已被占用」，或者牌桌上「上方写着 SOUTH、下方标着你自己」。

> 调试时可以用页面参数 `?seat=EAST` 临时改座位。

### 6.4 🔴 出牌方向是逆时针

```java
Seat.next() = (index + 3) % 4     // ✅ 逆时针
Seat.next() = (index + 1) % 4     // ❌ 会整局反向、上下家对调、进贡给错人
```

N→E→S→W 只是**罗盘编号**，不是出牌顺序。

**动`Seat.java` 之前先读 `SeatDirectionTest`**——它会告诉你对错。

### 6.5 🔴 三副牌的多重集不能用普通集合操作

三副牌意味着**同一点同花色有 3 张**。手牌相关的判断**严禁**使用 `removeAll` / `containsAll`，否则会误判：

```java
//❌ 错误：会把三张同牌当成一张处理
hand.removeAll(other);

// ✅ 正确：用项目提供的方法
Cards.containsCopies(hand, codes);
Cards.removeCopies(hand, codes);
```

### 6.6 🔴 改渲染代码必须用 destroyChildren

**绝不能直接 `node.removeAllChildren()`**。

直接移除不会触发子组件的 `onDestroy` → Graphics 顶点缓冲 / MaterialInstance / Label 贴图**永不归还** → 几分钟啃光显存 → `GL_OUT_OF_MEMORY` → `GL_CONTEXT_LOST_KHR` → **白屏只剩启动图**。

正确写法（`TableUI.destroyChildren`）：先 `children.slice()` 存一份 → `removeAllChildren()` 摘除 → 逐个 `Tween.stopAllByTarget` + `destroy()`（**先摘后毁**）。

⚠️ **这类显存泄漏在模拟器里测不出来**，改渲染必须真机长时间试跑。

项目里有 `installContextLostGuard()` 兜底：监听 `webglcontextlost` → 提示并自动刷新一次。

### 6.7 🔴 触摸回调用 TOUCH_START，不要用 TOUCH_END

真机上手指微滑就会触发 `TOUCH_CANCEL`，用 `TOUCH_END` 会导致「点了没反应」，而**模拟器完全测不出来**。

### 6.8 🟡 缩命中区要连子节点一起缩

手牌命中区压到 `spacing` 宽（约 44）后，改 `UITransform.contentSize` 时，**每个子节点的 UITransform 都要一起改**，否则点数/花色的 Label 会错位。

如果只是想让牌「看起来变大」，**用 `setScale`** —— scale 是节点级变换，命中区会自动跟随放大，不需要碰子节点。

### 6.9 🟡 选牌身份用复合身份 `code#occurrence`

比如 `H9#0`、`H9#1`：

- **不能存下标**（`#2`）→ 快照每次都会重排手牌，下标会整体错位
- **不能存纯代码**（`"H9"`）→ 三副牌同点同花有 3 张，点第2 张会被判成取消第 1 张

选牌集合必须用 `string[]`，**不要用 `Set<string>`**：

```ts
// ❌ Cocos 会把 [...set] 编译成 [].concat(set)，Set 不展开
// → JSON 序列化成 cards:[{}] → 服务端反序列化报错
const arr = [...someSet];       // ✅
```

验证方法：构建后在产物里搜 `selectedCodes`，确认是数组展开逻辑。

### 6.10 🟡 快照到达时不要清空选牌

`onSnapshotMsg` 里**不要 `clear()`**，用 `pruneSelected()` 剔除已经不存在的牌。否则每收到快照都要重新选一遍。

### 6.11 🟡 局域网 IP 变了要重新构建

手机连不上、顶栏卡「连接中…」——最常见的原因就是 **IP 变了**。

`serverUrl` 是**构建时注入**的，产物里写死了 IP。重跑构建脚本即可自动更新。

⚠️ 换个网络环境（换 WiFi、公司网、连VPN）IP 都会变。

### 6.12 🟡 真机只认 `wss://`

微信小游戏真机只支持 `wss://`，`ws://` 被硬屏蔽。**唯一例外**是手机端「开发调试 → 打开调试」模式（不校验域名）。

所以**「真机调试」能连，正式发布必须换 `wss://` + 已备案域名**。开发阶段用真机调试即可，别在这上面卡住。

### 6.13 🟡 顶栏的「已连接」和开发者工具的绿点不是一回事

- **顶栏「已连接」** = 手机↔ 战斗服（**这才是我们要的**）
- **开发者工具右上角绿点** = 手机 ↔ 开发者工具（工具通了不代表游戏通了）

排查顺序永远是：**先查战斗服端口是否在监听 → 再查客户端 IP → 最后才查微信工具**。

## 7. 常见问题速查

| 现象 | 大概率原因 | 怎么修 |
|---|---|---|
| 打开就黑屏，只剩启动图 | 显存泄漏（6.6）或 uuid 大写（6.2） | 查 uuid；查有无 `removeAllChildren` |
| 顶栏一直「连接中…」 | 战斗服没起 / IP 变了 | 起服务端；重跑构建 |
| 「⚠ 入座失败：座位已被占用」 | 两端座位不一致 | 检查是不是都填 SOUTH（6.3） |
| 点了没反应 | 用了 `TOUCH_END` | 改 `TOUCH_START`（6.7） |
| 牌面文字不清 / 点不准 | 手牌太挤 | 命中区是否缩窄但子节点没跟着缩（6.8） |
| 新加的命令完全无响应 | 改了 domain 但没 `mvn install`（5章） | `mvn install -DskipTests` |
| 整局方向反了 | 出牌顺序写成 index+1 | 检查 `Seat.next()`（6.4） |
| 主包超限 / 构建报错 | 用了 GUI 发布 | 用构建脚本（3.4） |
| 服务端抛 `NoSuchMethodError` | domain jar 是旧的 | `mvn install -DskipTests` |
